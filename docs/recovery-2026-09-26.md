# File-tree recovery investigation — 2026-09-26

## Evidence and limits

- Host: Obsidian 1.13.7, Windows, original Quiet Shelf 0.3.0.
- The initial persisted state had focus enabled for one nested folder. A run of
  the actual plugin predicate reproduced the other top-level folders being hidden.
- In the live app, the original Exit focus command restored the tree on this run.
  A universal failure of that command, or of ordinary plugin disabling, was not
  reproduced. Do not treat the user's original timing as fully established.
- Independent failing regressions exposed real recovery defects: Restore did
  not unblock focus or shelved ancestors; rendering waited for a settings write;
  callbacks could reapply hiding after unload.

## Fix boundary

Only Quiet Shelf code, styles, translations and documentation were changed.
Restore now exits focus when needed and restores blocking shelved ancestors;
unrelated shelf entries, focus targets and saved sets are kept. Display updates
happen before disk writes, with an explicit warning on persistence failure.
Unloaded instances cannot observe, schedule or apply hiding again.

## Verification

- Before the fix: 7 of the initial 12 shipped-plugin regression tests failed;
  a separately added focus-status exit-control test also failed before implementation.
- After the fix: all 13 tests pass with `node --test tests/recovery.test.js`.
- `node --check main.js` and the existing external strict-load test pass.
- Chinese/English locale keys and placeholders match; translations are rebundled.
- Sync copied the six plugin files to the user vault, config repository and demo
  vault; all copies matched the source byte-for-byte. The sync script did not
  write `data.json`.
- Live app: normal tree on launch; focus on/off through the new shelf-panel exit;
  disabling Quiet Shelf while focused restored both focus-excluded and shelved
  entries; re-enabling worked; a shelve/restore round trip outside the focus set
  exited focus and restored the tree with the explanatory notice.
- The runtime settings differed from their pre-test backup only in
  `focusActive: true -> false`. No note content was edited. After the disable /
  enable test, Quiet Shelf was put back in its original plugin load-list position.
- A final full app restart with that original load order kept the tree restored
  and focus off. Obsidian is left open with Quiet Shelf enabled.

## Not part of this repair

- No other plugin implementation, custom sorting, sponsorship account or payment
  details were changed.
- No GitHub tag, Release or push is included in this local repair.
- Delayed/failing disk writes and unload races were verified in the regression
  harness; they were not artificially induced in the user's live vault.
